# Host PC ↔ 웹 시뮬레이션 통신 시험

실제 버거·로봇팔·센서 대신 브라우저가 기존 시나리오를 실행하고 완료 신호를 보냅니다. 호스트는 완료 회신을 검증한 후 다음 작업 완료 지점까지의 실행을 지시합니다. 이동 중 회전·전진·후진·경유 노드는 하나의 이동 작업으로 이어서 실행합니다. 다른 장비의 완료 시각이 주행 도중에 겹쳐도 로봇을 중간에서 멈추지 않도록, 모든 주행 로봇이 목적지에 도달한 경계에서만 다음 지시를 기다립니다. 그동안 발생한 이벤트는 모두 회신에 포함합니다. 장비별 독립 ROS 작업 스케줄러가 아니라 기존 공정 시나리오를 이용한 통신 시험입니다.

## 실행

Python 3.10 이상만 필요합니다. 별도 패키지나 Node 설치는 필요 없습니다.

1. 웹사이트의 **호스트 시험 파일 다운로드**로 ZIP을 받아 압축을 풉니다.
2. `robot3-host-test` 폴더에서 `python3 host/server.py` 실행. Windows에서는 `py -3 host/server.py`도 가능합니다.
3. **http://127.0.0.1:8082/?host=1** 을 같은 PC의 브라우저에서 엽니다. 호스트 연결은 자동으로 시도됩니다.
4. A제품 수량을 입력하고 **주문 · 시작**을 누릅니다.
5. **다음 단계**를 누르면 호스트 지시를 받아 다음 작업 완료 지점까지 움직이고 완료를 회신합니다.
6. **완료 회신 후 자동으로 다음 단계**를 켜면 매번 ACK를 받은 뒤 자동으로 이어집니다.
7. **일시정지 / 재개**, **시험 초기화**, **통신 기록**으로 동작을 확인합니다.

포트가 사용 중이면 `python3 host/server.py --port 8083`으로 실행하고 출력된 주소를 엽니다. 종료는 Ctrl+C입니다. GitHub Pages는 정적 웹사이트이므로 Python 서버를 실행할 수 없습니다. 통신 시험은 위 로컬 주소에서 하고, 공개 주소에서는 기존 자동 재생을 사용할 수 있습니다.

## 신호와 상태

`POST /api/connect → start → [실행 → ack → next] → done`

- 모든 요청: `client_id`, 변경 요청: `message_id`.
- `start`: `quantity` (정수 1~20). 호스트가 `order_id` 발급.
- `next`: 다음 작업 완료 지점까지의 단계 지시. 실행 중에는 거부.
- `ack`: `order_id`, `seq`, `time`. 현재 지시한 단계와 시간만 인정.
- `auto`: `enabled` boolean. 매 완료 회신 이후 호스트가 다음 지시 생성.
- `pause`, `resume`, `reset`, `disconnect`: 운영자 제어.
- `heartbeat`: 브라우저가 0.5초마다 전송. 5초 넘게 없으면 진행 중인 주문은 paused로 전환.
- `GET /api/state`: 현재 호스트 상태/지시/카운트/최근 통신 기록 확인.
- 상태: `idle → running → waiting → running … → done`; 오류/연결 단절은 `paused` 및 명시적 재개.
- 카운트는 호스트가 해당 단계의 완료 회신을 인정한 뒤 화면에 반영. 동시 작업의 완료가 주행 중에 발생하면 주행 완료 경계에서 함께 반영.
- 동일 완료와 동일 메시지 재전송은 중복 집계하지 않음. 이전 주문/미래 단계의 ACK는 거부.
- 실행 중 되감기·로컬 재생·시간 이동은 막으며 배속은 애니메이션 속도만 변경.
- 연결 실패 시 브라우저는 즉시 재생을 중지. 서버는 5초 제한시간을 상태 조회/다음 요청 시 판정하고 재개 지시를 요구.
- 서버 재시작 시 주문 상태는 초기화. 화면 새로고침은 마지막 호스트 완료 지점부터 미완료 구간을 다시 재생할 수 있음(실물 동작 재실행 정책 아님).
- 한 브라우저 세션만 제어 가능. 다른 화면의 접속은 거부. 기존 화면 연결 해제 또는 서버 재시작 후 교체.

## 범위

127.0.0.1에서만 수신하며 실제 ROS 토픽, 모터, 센서, 와플은 연결하지 않습니다. HTTP/JSON으로 명령·회신의 경계를 시험합니다. 실제 장비 연결 때는 장비별 완료/실패 상태, 작업영역 이탈 확인, 센서 확인, 별도 제한시간과 재시도 정책을 장비 어댑터에 구현해야 합니다. 현재 완료는 웹의 시뮬레이션 시간 도달 의미입니다.

공정·이동 규칙은 engine.js가 원본입니다. 개발자가 엔진을 바꾸면 `node host/build_scenarios.cjs`로 호스트 단계 데이터를 다시 생성해야 합니다. GitHub 배포는 자동으로 재생성하고 검증합니다.

## 개발 검증

```sh
node host/build_scenarios.cjs
node tests/engine.test.cjs
python3 -m unittest discover -s tests -p 'test_host.py' -v
python3 host/package.py
```


## 업데이트했는데 이전처럼 보이는 경우

`git pull`만으로 이미 실행 중인 Python 서버의 메모리가 갱신되지는 않습니다. 기존 서버 터미널에서 Ctrl+C → `git pull` → `python3 host/server.py` 순으로 다시 실행하고 로컬 화면을 새로고침하세요. 화면에 **목적지 단위 v2 · 2개 주문 8단계**가 표시되면 새 서버입니다. **구버전 호스트 서버**가 표시되면 이전 서버가 포트를 사용 중입니다. 다른 폴더의 서버인지 실행 터미널의 경로를 확인하거나 `--port 8083`으로 새 서버를 실행하고 새 주소로 접속하세요.

중간 코너에서 차체가 제자리 회전하는 동작은 유지됩니다. 회전이 끝나면 버튼 조작 없이 이어서 움직여야 합니다. 목적지 도착 후 수동 승인 대기는 정상이며 자동 진행 체크로 이어서 실행할 수 있습니다.

## 단계별 실행과 전환 조건 (2026-09-28)

- 주문 시작 옆 **단계별 실행**을 누르면 첫 단계를 실행하고 목적지·작업 완료 경계에서 기다립니다. **다음 단계 실행**으로 이어갑니다. 회전 코너·주행 중간에는 추가 대기하지 않습니다.
- 시뮬레이션 왼쪽의 전환 조건: 빨간 동그라미는 미완료, 초록 동그라미는 완료입니다. 도착, 적재 3개, 조립, 리니어 준비·원점, 파렛트 완료와 해당 운송의 선행 조건을 표시합니다.
- Host 연결 상태에서 단계별 실행을 누르면 자동 진행을 해제하고 `start` 또는 `next`를 보냅니다. 작업 완료 후 `order_id / seq / time`을 포함한 ACK를 보내며, Host 응답의 `acked_seq`가 확인돼야 ACK 항목이 초록색이 됩니다.
- 작업 조건은 웹 시뮬레이션의 모의 완료 이벤트입니다. 실제 로봇의 Nav2·ArUco·후방 IR 센서 신호는 아직 연결되지 않았습니다. 연결이 끊기면 다음 단계 버튼이 비활성화됩니다.
- 기존 주문 시작과 Host 자동 진행 체크박스는 그대로 사용할 수 있습니다. 로컬 시험은 최신 소스를 `git pull`한 뒤 서버를 재시작하고 브라우저를 새로고침하세요.

## 관리자 설정

`http://127.0.0.1:8082/admin.html`에서 시뮬레이션 속도·공정 시간을 조절하고 `config.js`로 내보낼 수 있습니다. 브라우저 저장값은 단독 시뮬레이션에만 적용합니다. Host 설정을 바꾸려면 서버를 종료하고 프로젝트 루트의 config.js를 교체한 뒤 `node host/build_scenarios.cjs`를 실행하고 서버를 다시 시작하세요. 생성에는 Node.js 22 이상이 필요합니다. 서버가 설정을 화면에 전달하므로 Host ACK 시간과 화면 시간이 일치합니다. 상세 내용은 ZIP 루트의 CONFIG_GUIDE.md를 참고하세요.

## 새 다운로드 패키지 경로

최신 ZIP 루트는 `robot3_host/`입니다. 전체 개발 안내는 루트 README.md를 확인하세요. 위 문서의 프로젝트 루트는 패키지에서는 `web/`에 해당하므로, ZIP 루트에서 실행할 때 `python3 web/host/server.py`를 사용합니다. 시스템 설정 원본은 `config/system-config.json`, 시뮬레이션 속도 설정은 `web/config.js`입니다.

## 실장치 관제 화면

`http://127.0.0.1:8082/control.html`은 별도 실장치 관제 페이지입니다. 기존 `/?host=1`의 시뮬레이션 시간표/웹 ACK를 사용하지 않습니다. 현재는 화면과 Host 어댑터용 상태·명령 API만 제공하며, 실제 ROS 2 Action 어댑터는 구현 전입니다. [연결 계약](../HOST_CONTROL_GUIDE.md)을 참고하세요.
