실물 테스트 사용방법

매일 쓰는 실행·종료 순서입니다. 명령은 관제 PC 터미널에서 실행하세요.

이 안내의 hostamr · hostrun는 이 관제 PC의 $HOME/final_project에 설정한 명령입니다.

처음 실행서버 켜기·끄기
전원·배치→M1·M2 준비→관제 실행→1개 수동 시험

자재창고·조립대 오류 초기화: 모든 장치 정지·초기 배치 확인 후 해당 장치 카드의 버튼을 누릅니다. 남은 팔 작업 종료 확인 후 실패 주문을 비웁니다. 원점 복귀·공정 재개·M1/M2 정지 잠금 해제는 하지 않습니다. 작업이 실행 중이면 거절되며, 자재창고는 업데이트된 팔1 서버가 연결되어야 사용할 수 있습니다. 하드웨어 정리가 확인되지 않은 오류는 현장 점검이 필요합니다.

01

전원과 초기 배치 확인

현장

M1·M2·로봇팔·제어 PC의 전원을 켜고 같은 네트워크에 연결합니다. M1·M2는 각각 지정 주차 위치와 방향에 놓고, 자재·지그와 작업 공간을 준비합니다.

--parked는 현재 위치를 지정 주차 위치로 설정합니다. 다른 위치에 있으면 사용하지 마세요.

02

호스트에서 M1·M2 준비

관제 PC 터미널
hostready

M1 → M2 순서로 센서·위치·제어 서버를 준비합니다. 전원을 켠 뒤 실물 시험을 준비할 때 사용하세요.

모터 토크를 켜고 정지 잠금을 해제합니다. 목적지 이동은 요청하지 않습니다.

두 로봇 모두 준비 결과 success: true → 상태 mode: process, busy: false를 확인하세요.

실패하거나 연결이 끊기면 결과를 확인한 뒤 진행하세요. 서버만 켜려면 아래 서버 켜기·끄기의 hostamr를 사용합니다.

03

관제 실행과 연결 확인

관제 PC 터미널
hostrun

새 실물 관제 실행 시: 서버 확인 → 팔의 중단 작업 정리·M1/M2 정지 잠금 해제 → 팔1 A 시작 자세 → 팔2·3 저장 안전 자세 → 리니어 수축 위치 → 웹화면 순서로 준비합니다. 준비 이동 전 작업 공간과 적재물을 확인하세요.

진행 중인 작업이나 정지 미확인 상태에서는 준비를 중단합니다. 이전 이동을 재개하거나 주차 좌표를 재설정하지 않습니다. 리니어는 기존 두 위치 중 뒤로 들어간 위치를 사용합니다.

미정리 주문이 있으면 잠금 해제·이동 준비를 생략하고 복구 화면을 엽니다. 실패 주문을 정리한 뒤 hoststop → hostrun으로 다시 준비하세요. 준비 없이 화면만 열려면 hostrun --no-arm-prepare를 사용하세요.

관제가 이미 켜져 있으면 중복 실행하지 않고 화면을 엽니다. 새로 실행한 터미널은 켜 두세요.

관제 종료: 다른 터미널에서 hoststop. 관제 웹·ROS 연결·백엔드를 종료하며 로봇 서버 종료나 비상정지는 하지 않습니다. 초기 위치 준비 중이라면 실행 중인 터미널에서 Ctrl+C를 누르세요.

http://localhost:8082/control.html에서 Host · M1 · M2 · 자재창고(팔1) · 제작공정(팔2·3) 연결을 확인합니다. 1개 시험도 현재 관제에서는 다섯 장치의 Action 서버 연결이 필요합니다.

서비스의 active / running과 웹 관제 연결은 별개입니다. 연결되지 않으면 주문 시작을 보류하세요.

GitHub Pages는 안내·시뮬레이션용입니다. 실제 로봇 제어는 관제 PC의 위 로컬 주소에서 실행합니다.

04

첫 시험은 1개씩, 수동으로

웹 관제 화면
실제 자재에 맞는 A/B 선택수량 1개자동 진행 체크 해제주문 시작

‘주문 시작’을 누르면 M1의 창고 이동이 바로 시작됩니다. 각 동작이 끝나고 현장 상태를 확인한 뒤 ‘다음 단계’를 누르세요.

M1 창고 도킹 → 팔1 자재 적재 → M1 제작공정 도킹 → 팔2 조립 → 팔3 완제품 적재 → M1 복귀

완료 기준: 모든 단계 완료, 적재 완료 1, 주문 완료. 연결 표시만으로 물리적인 준비 완료를 판단하지 않습니다.

실패한 시험 초기화

관제 PC
hostreset

로봇·리니어의 정지와 작업 종료, 초기 배치·자재 상태를 확인한 뒤 초기화를 입력하세요. 웹의 실패 주문 초기화 버튼으로도 가능합니다.

현재 위치에서 이어가려면: 관제의 실패 단계 재시도를 누르세요. 해당 단계 처음부터 다시 실행하며 기존 자동 진행 설정을 유지합니다. 자동 진행이 켜져 있으면 성공 후 다음 단계로 이어지고, 꺼져 있으면 다음 단계 버튼을 기다립니다. 일부 동작이 끝났다면 해당 단계의 시작 조건으로 자재와 위치를 복구한 뒤 사용하세요.

로봇 제어 팝업: 관제 상단의 로봇 제어에서 M1·M2 상태와 목적지 버튼을 사용할 수 있습니다. 진행 중인 주문에서는 목적지 변경이 잠깁니다.

M1·M2 위치 복구: 장치 카드에서 목적지를 선택하고 수동 이동을 누르세요. 주문 대기·완료 상태 또는 실패 주문의 작업 종료 후 사용할 수 있습니다. 이동 중에는 새 주문·추가 수동 이동·재시도가 잠깁니다. 주문 단계·수량은 바뀌지 않습니다. GO_TO 오류가 났다면 해당 로봇의 이동 오류 초기화를 누르세요. 실패 주문을 보관·초기화한 뒤 해당 로봇의 정지 잠금을 해제합니다. 현재 좌표와 적재물은 바뀌지 않으므로 초기 배치를 복구한 뒤 새 주문을 시작하세요. 오류 원인 해결이나 도킹 완료를 뜻하지 않습니다.

실패 기록을 보관하며, 필요한 정지 응답을 확인한 뒤 주문을 비웁니다. 이동·정지 잠금 해제·주차 좌표 설정은 하지 않습니다. 연결이 끊겼거나 진행 중인 주문은 초기화할 수 없습니다.

로봇팔 정지·해제: 자재창고의 팔1 정지, 제작공정의 팔2·3 정지를 사용하세요. 정지 해제·재개는 중단 동작을 이어갈 수 있습니다. 제작공정 리니어는 이 정지 명령에 포함되지 않습니다. 오류 상태에서 거절되면 정지 완료로 간주하지 마세요.

초기화 후 지정 주차 위치에서 hostready → hostrun. 첫 시험은 1개·자동 진행 해제로 시작하세요.

서버 켜기·끄기

아래 명령은 모두 관제 PC 터미널에서 실행합니다.

M1·M2 서버 켜기 / 상태 확인

관제 PC
두 제어 서버 시작 · 다시 켜기도 같은 명령
hostamr
두 서버 상태 조회
hostamr --status

active / running이면 실행 중입니다. 이미 실행 중인 서버는 유지하며 재시작하지 않습니다. 서버 시작만으로 센서·모터·초기 위치 준비가 끝나는 것은 아닙니다.

M1·M2 서버 끄기

관제 PC

아래 robot 계정과 192.0.2.101 / 192.0.2.102 주소는 예시입니다. 실제 로봇의 계정·IP로 바꿔 실행하세요.

주문과 로봇 동작이 모두 끝나고 실제 정지를 확인한 뒤 실행하세요. 서버 종료는 비상정지가 아닙니다.

M1 제어 서버 종료
ssh robot@192.0.2.101 'systemctl --user stop m1-action.service'
M2 제어 서버 종료
ssh robot@192.0.2.102 'systemctl --user stop m2-action.service'

종료 후 hostamr --status에서 inactive / dead를 확인합니다. 위 명령은 Action 서버만 종료하며 센서·Nav2 서비스나 로봇 전원을 끄지는 않습니다.

다시 켜려면 hostamr를 실행하고, 실물 시험 전에 준비 결과와 관제 연결을 다시 확인하세요.

호스트 웹 관제 끄기 / 다시 켜기

hostrun 실행 터미널

모든 작업이 끝나고 장치가 멈춘 상태에서 hostrun을 실행한 터미널의 Ctrl+C를 누릅니다. 웹 관제·ROS 브리지·Host 제어기를 함께 종료합니다.

다시 켜려면 관제 PC에서 hostrun을 실행합니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다. M1·M2 원격 서버는 위 종료 명령으로 따로 끕니다.

공정 자동 진행

주문 시작 때 M1 이동과 리니어 조립 위치 준비를 함께 시작합니다. 이후 선행 작업이 완료되면 독립된 작업을 함께 시작합니다. M2 대기장소 이동과 팔1 적재, 팔2 조립과 M2 자재창고 이동, 팔3 적재와 조립 완료 로봇의 출발을 병렬로 실행합니다. 팔2·팔3는 BUILD_LOAD_A/B 연속 명령 한 번으로 실행합니다.

공용 통로의 이동로봇은 한 대씩 이동합니다. 다음 로봇은 앞 로봇의 출차와 팔3 적재가 모두 끝나야 조립대에 들어갑니다. 일시정지는 실행 중인 모든 작업 완료 후 적용됩니다. 실패 단계 재시도는 완료한 작업을 반복하지 않습니다.

정지가 필요하면: ‘단계 후 일시정지’는 현재 동작이 끝난 뒤 적용됩니다. M1·M2는 관제의 장치별 정지 버튼, 팔은 해당 제어기의 정지를 사용합니다. 팔2·3의 정지 명령은 이미 움직이는 리니어까지 멈추지는 않습니다.

팔1 서버 종료는 토크를 해제하므로 팔을 지지한 상태에서 종료하세요. 브라우저 닫기·서버 종료는 즉시 정지 명령이 아닙니다.

명령을 찾을 수 없다고 나오면 현재 터미널에서 source ~/.bashrc를 한 번 실행하세요.
