01

전원과 초기 배치 확인

현장

M1·M2·로봇팔·제어 PC의 전원을 켜고 같은 네트워크에 연결합니다. M1·M2는 각각 지정 주차 위치와 방향에 놓고, 자재·지그와 팔의 작업 공간을 준비합니다.

아래 --parked는 현재 위치를 지정 주차 위치로 설정합니다. 주차 위치가 아니면 사용하지 마세요.

02

M1 준비

10.10.142.104
관제 PC의 새 터미널 → M1 접속
ssh ubuntu@10.10.142.104
접속 성공 후, M1 터미널에서
python3 ~/AMR/scripts/robot.py --robot M1 host-ready --parked
python3 ~/AMR/scripts/robot.py --robot M1 status

확인: 준비 결과 success: true → 상태 mode: process, busy: false

M1의 계정은 설치 문서 기준 ubuntu로 표기했습니다. SSH 인증이 거절되면 실제 계정과 키를 확인하세요. 접속 실패 상태에서 오른쪽 명령을 관제 PC에 실행하지 마세요.

04

관제 실행

이 관제 PC
source ~/.bashrc
hostrun

로봇에 SSH로 접속한 터미널이 아닌 관제 PC의 새 터미널에서 실행하고 켜 두세요. 관제가 이미 실행 중이면 중복 실행하지 않고 화면을 열면 됩니다.

관제 PC에서 http://localhost:8082/control.html을 열고 Host · M1 · M2 · 자재창고(팔1) · 제작공정(팔2·3)의 연결을 확인합니다. 팔이 연결되지 않으면 아래 ‘팔 서버 연결이 안 될 때’를 확인하세요.

GitHub Pages에서는 안내와 시뮬레이션을 볼 수 있습니다. 실제 로봇 제어는 관제 PC의 위 로컬 주소에서 실행합니다.

‘주문 시작’을 누르면 M1의 창고 이동이 바로 시작됩니다. 각 동작이 끝나고 현장 상태를 확인한 뒤 ‘다음 단계’를 누르세요.

M1 창고 도킹 → 팔1 자재 적재 → M1 제작공정 도킹 → 팔2 조립 → 팔3 완제품 적재 → M1 복귀

완료 기준: 6 / 6 단계, 적재 완료 1, 주문 완료. 연결 표시만으로 물리적인 준비 완료를 판단하지 않습니다.

팔 서버 연결이 안 될 때

팔1 · 모방학습 제어 PC

팔1에 연결된 PC에서 실행합니다. 관제 화면에 이미 연결되어 있으면 서버를 중복 실행하지 마세요.

cd ~/Downloads/so101_imitation
bash run-arm1-server.sh

ARM1 READY mode=HARDWARE 표시를 확인하고 터미널을 유지합니다. 폴더나 모델이 없으면 팔1 PC의 실제 설치 경로를 확인하세요.

팔2·3 · 공용 제어 Pi

관제 PC 터미널에서 접속 
ssh ubuntu@10.10.142.113
Pi에 접속한 뒤, 서비스 확인 
systemctl is-active arm3-linear-controller.service workcell-actions.service

둘 다 active이면 그대로 둡니다. inactive인 경우에만 아래 명령으로 시작합니다.

sudo systemctl start arm3-linear-controller.service workcell-actions.service

failed 또는 not-found이면 시작을 반복하지 말고 설치·로그를 확인합니다. 작업 중에는 서비스를 재시작하지 마세요.

환경 점검 / 모의 실행 / 연결 문제

아래 명령은 관제 PC에서 실행합니다. 현재 관제를 종료한 상태에서 하나씩 사용하세요.

hostcheck

환경·Action 타입·8082/9090 포트를 점검합니다. 관제가 이미 켜져 있으면 포트가 사용 중인 것이 정상입니다.

hostmock

실제 장치 대신 가상 장치로 실행합니다. 실물 시험에는 hostrun을 사용하세요.

장치가 보이지 않으면 같은 네트워크인지, ROS_DOMAIN_ID=40 / ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET인지 확인합니다. ‘서비스 active’와 ‘관제에 연결됨’은 별도로 확인해야 합니다.

종료: 모든 장치의 동작 완료·정지를 확인한 뒤 관제를 실행한 터미널에서 Ctrl+C를 누릅니다. ‘단계 후 일시정지’는 현재 동작이 끝난 후 적용되며, 브라우저 닫기·관제 종료는 즉시 정지 명령이 아닙니다. 팔1 서버 종료는 토크를 해제하므로 팔을 지지한 상태에서 종료하세요.

정지가 필요하면: M1·M2는 관제의 장치별 정지 버튼을 사용합니다. 팔은 해당 제어기의 정지를 사용하며, 팔2·3의 정지 명령은 이미 움직이는 리니어까지 멈추지는 않습니다.
