# Robot3 공정 시뮬레이션

10월 7일 1차 목표인 A제품 주문 → 부품 적재 → 운반 → 티칭 조립 → 파렛트 적재 → 복귀를 웹에서 재생합니다. 실제 로봇 제어는 없습니다. 선택적으로 웹 상태를 ROS 토픽으로 송신하는 시험 기능을 제공합니다. 기존 Burger1/Burger2 작업공간은 변경하지 않습니다.

## 열기

- **웹 접속:** [Robot3 공정 시뮬레이션](https://7s-fa.github.io/host_web/) — GitHub Pages 배포 완료 후 이용할 수 있습니다.
- **설치 없이:** `robot3-simulation.html` 한 파일을 PC로 내려받아 브라우저에서 엽니다. 사진 9장과 한글 폰트도 포함되어 있어 인터넷 없이 동작합니다.
- **로컬 서버:** `bash start.sh` 실행 후 `http://localhost:8082`에 접속합니다.
- **VS Code Remote SSH:** Ports 탭에 `8082`를 추가하고 전달된 localhost 주소를 엽니다. 서버는 기본적으로 127.0.0.1에만 바인딩됩니다.

## 화면 구성

- 왼쪽: 큰 공정 시뮬레이션 지도, 재생 제어, 장비 상태, 현재 공정 사진·이벤트.
- 오른쪽: 실제 조작 가능한 Host PC GUI. 제품·수량 입력, 주문 시작, 주문 수량·운송 잔여·완제품 잔여·적재 완료 카운트를 함께 표시합니다.
- 모바일: Host GUI를 위에, 시뮬레이션을 아래에 배치합니다.

## 조작

1. Host PC 주문에서 A제품 수량을 입력합니다. 1차 목표 시연은 2개이며 1~20개까지 반복 흐름을 확인할 수 있습니다.
2. `주문 · 시작`을 누르면 운송 잔여와 완제품 잔여를 주문 수량으로 초기화합니다.
3. 일시정지, 이전/다음 이벤트, 진행 막대, 0.5/1/2/4배속을 사용합니다.
4. 지도 구역을 누르면 그 장소의 사진을 표시합니다. `자동`으로 현재 공정 사진을 따라갈 수 있습니다.
5. 사진을 누르면 확대합니다. 현장 사진 탭에는 전체 사진이 있습니다.
6. `기록 내려받기`는 현재 시점까지의 이벤트·카운트를 JSON으로 저장합니다.
7. 새 주문 수량을 바꾸려면 `초기화`를 누릅니다. 완료 후에는 바로 새 주문을 넣을 수 있습니다.

## 공정 규칙

- 제품 1개당 부품 3개. 버거 1부터 시작해 버거 2와 번갈아 운반합니다.
- 운송 잔여: 적재가 끝난 버거의 제작공정 이동 시작 시 한 번 감소합니다.
- 완제품 잔여: 로봇팔 3의 파렛트 적재 성공 시 한 번 감소합니다.
- 주문이 2개 이상이면 버거 1이 자재창고에 도착하는 순간 버거 2가 초기위치에서 대기장소로 출발합니다. 1개 주문에서는 버거 2가 초기위치에 머뭅니다.
- 첫 조립이 시작되면 다음 버거가 자재창고에서 부품을 준비합니다.
- 제작공정에는 중앙 교차 통로에서 오른쪽으로 직선 이동해 도킹합니다. 도킹 직전 추가 꺾임은 없습니다.
- 출발 방향이 다르거나 코너에 도착하면 이동을 멈추고 차체를 제자리 회전시킨 뒤 직선 주행합니다. 회전은 90도당 1초의 설명용 시간으로 부드럽게 표시하며 공정 일정에도 포함합니다. 전진 구간에서는 버거 전방이 진행 방향을 향하고, 후진 구간에서는 바라보는 방향을 유지하며 뒤로 이동합니다. 대기장소에는 아래쪽을 바라보며 전진 주차합니다. 출차는 10cm 후진·정지 → 180도 회전 → 전진 주행합니다.
- 초기위치에서 두 버거는 왼쪽 벽의 ArUco 마커를 바라봅니다. 전방 카메라로 마커에 정렬하고 후방 IR 센서가 검은 감지선을 감지하면 멈추는 기준입니다.
- 초기위치 → 창고: 왼쪽을 바라본 채 중앙 통로까지 후진 → 우회전 90도 → 위쪽 창고로 전진.
- 창고 → 공정: 위쪽을 바라본 채 교차 통로까지 후진 → 우회전 90도 → 오른쪽 공정으로 전진 도킹.
- 공정 → 초기위치: 제작공정에서 로컬 10cm 후진·정지 → 제자리 180° 회전 후 전진으로 복귀합니다. 버거 1은 WP3 → WP1, 버거 2는 WP3 → WP4를 지나 각 초기위치로 복귀합니다. WP4는 버거 2의 출차·복귀 합류점입니다. 경유점에서는 Host의 별도 승인을 기다리지 않습니다.
- 대기장소 → 초기위치: 10cm 후진·정지 후 180도 회전하고, 중앙 통로를 전진해 해당 주차칸 높이에서 좌회전한 뒤 진입합니다. 두 버거 모두 왼쪽 벽을 바라보며 복귀 완료합니다.
- 대기장소에는 ArUco 마커가 없으며 전진 주차 중 후방 IR 센서가 검은 감지선을 감지하면 정지합니다. 다른 목표 위치에는 ArUco 표식과 후방 적외선 센서용 검은 감지선을 표시합니다. 현재 표식은 개념 표시이며 실제 마커 ID·사전·센서 신호 판정은 실물 설정 시 확정합니다.
- 다음 제작공정 운송은 앞 제품의 파렛트 적재, 앞 버거의 대기장소 도착, 다음 부품 3개 적재를 모두 확인한 뒤 시작합니다.
- 리니어 모터는 매 제품마다 A지그 준비 → 조립 → 초기위치 복귀를 수행합니다.
- 운송 잔여가 0이어도 마지막 운송 버거가 제작공정에 도착·도킹할 때까지 다른 버거는 대기장소에 머뭅니다. 도킹 완료 후 대기 버거가 초기위치로 복귀합니다. A제품 2개 주문에서는 버거 2 도킹 완료 → 버거 1 복귀 순서입니다. 마지막 버거는 자신의 조립 작업 완료 후 초기위치로 복귀합니다.
- 마지막 완제품 적재와 두 버거 복귀가 모두 끝나야 주문 완료입니다.

사진은 제공된 Drive 폴더에서 가져왔으며 출처는 `assets/sources.json`에 있습니다. 사진은 웹용으로 축소했습니다. 지도는 제공된 사진 기준의 세로형 배치입니다. 사용자가 지정한 방향인 왼쪽 아래 초기위치(B1 위·B2 아래), 중앙 위 자재창고, 오른쪽 아래 제작공정을 중앙 통로로 연결합니다. 교대 대기장소는 전체 맵 사진에서 중앙 아래쪽 테이프 박스로 표시된 곳입니다. 제작공정은 같은 작업대 위에 조립 로봇팔 2, 가로 리니어 지그, 적재 로봇팔 3과 파렛트를 배치했습니다. 사진에서 파악한 상대 배치이며 실측 좌표나 충돌 회피 경로는 아닙니다. 각 동작의 시간은 설명용 고정값으로 실측값이 아닙니다. 3개 이상 주문은 동일 규칙을 교대로 반복한 확장 시나리오입니다. 실패·재시도는 이 버전에 포함하지 않았습니다.

## 파일과 검증

- `engine.js`: 주문별 일정과 시점별 상태 계산. 외부 의존성 없음.
- `app.js`, `index.html`, `styles.css`: 지도, 재생, 사진, 이벤트 UI.
- `tests/engine.test.cjs`: 주문 1/2/3/4/5/10/20개, 카운트, 부품 수, 교대 조건, 장비 중복 사용, 복귀, 시간 되감기 검증. `node tests/engine.test.cjs`로 실행.
- `tests/browser.cjs`: Playwright 기반 화면/상호작용 검증. Playwright 설치 후 로컬 서버를 켜고 `node tests/browser.cjs`로 실행합니다. 별도 설치 경로는 `PLAYWRIGHT_MODULE` 환경변수로 지정합니다.
- `build_standalone.py`: 이미지·폰트를 포함한 단일 HTML 생성. 수정 후 `python3 build_standalone.py` 실행.
- 폰트: Pretendard 1.3.9, SIL Open Font License. `assets/FONT-LICENSE.txt` 참고.

## GitHub Pages 공개

1. GitHub에 공개 저장소를 만들고 이 폴더의 파일을 저장소 루트에 올립니다. `index.html`과 `assets/`가 루트에 있어야 합니다.
2. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 지정합니다.
3. `main` 브랜치에 push하거나 **Actions → Publish simulation to GitHub Pages → Run workflow**를 실행합니다.
4. 엔진 테스트 통과 후 배포됩니다. 완료 주소는 **Settings → Pages** 또는 Actions 배포 결과에서 확인합니다.

공식 절차: [GitHub Pages 사용자 지정 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
사이트는 HTML/CSS/JavaScript와 로컬 사진·폰트만 사용하므로 별도 백엔드나 API 키가 필요하지 않습니다.
단일 HTML은 생성 산출물이므로 Git에서 제외했습니다. 필요한 경우 `python3 build_standalone.py`로 다시 만듭니다.


## 호스트 PC 통신 시험

공개 웹사이트의 **호스트 시험 파일 다운로드**를 받아 압축을 푼 뒤, 그 폴더에서 `python3 host/server.py`를 실행하고 `http://127.0.0.1:8082/?host=1`에 접속합니다. Python 3.10 이상만 필요합니다. 이 저장소에서는 같은 명령으로 바로 실행할 수 있습니다.

호스트가 중간 노드에서 끊지 않고 다음 작업 완료 지점까지의 실행을 지시하고 웹이 완료를 회신합니다. **다음 단계**, **완료 회신 후 자동 진행**, **일시정지·재개**, **시험 초기화**, **통신 기록**을 제공합니다. 완료 신호 중복·순서 오류·이전 주문 신호를 검사하며 통신 실패 시 정지합니다. 실제 장비는 연결하지 않습니다. 기존 자동 시뮬레이션은 공개 사이트에서 그대로 사용할 수 있습니다.

실행 방법과 프로토콜: [host/README.md](host/README.md).

## 단계별 실행과 전환 조건 (2026-09-28)

- 주문 시작 옆 **단계별 실행**을 누르면 첫 단계를 실행하고 목적지·작업 완료 경계에서 기다립니다. **다음 단계 실행**으로 이어갑니다. 회전 코너·주행 중간에는 추가 대기하지 않습니다.
- 시뮬레이션 왼쪽의 전환 조건: 빨간 동그라미는 미완료, 초록 동그라미는 완료입니다. 도착, 적재 3개, 조립, 리니어 준비·원점, 파렛트 완료와 해당 운송의 선행 조건을 표시합니다.
- Host 연결 상태에서 단계별 실행을 누르면 자동 진행을 해제하고 `start` 또는 `next`를 보냅니다. 작업 완료 후 `order_id / seq / time`을 포함한 ACK를 보내며, Host 응답의 `acked_seq`가 확인돼야 ACK 항목이 초록색이 됩니다.
- 작업 조건은 웹 시뮬레이션의 모의 완료 이벤트입니다. 실제 로봇의 Nav2·ArUco·후방 IR 센서 신호는 아직 연결되지 않았습니다. 연결이 끊기면 다음 단계 버튼이 비활성화됩니다.
- 기존 주문 시작과 Host 자동 진행 체크박스는 그대로 사용할 수 있습니다. 로컬 시험은 최신 소스를 `git pull`한 뒤 서버를 재시작하고 브라우저를 새로고침하세요.

## 관리자 설정

상단 **관리자 설정**에서 버거별 전진·후진·회전 속도를 변경할 수 있습니다. 공정 작업 시간은 화면에서 숨기고 `config.js`의 `process` 값으로 관리합니다. 브라우저 저장, 기본값 복원, config.js 내보내기와 JSON 백업을 제공합니다. 실제 로봇 제어가 아닌 시뮬레이션 설정입니다.

기본값은 루트 `config.js`에서 유지보수합니다. Host는 서버 시간표에 대응하는 설정을 사용하며, 변경 후 `node host/build_scenarios.cjs` 실행과 서버 재시작이 필요합니다. 상세 절차와 필드 설명은 [CONFIG_GUIDE.md](CONFIG_GUIDE.md)를 참고하세요.

## Host 실장치 관제 화면

[웨이포인트 화면](waypoints.html)은 공개된 버거 1의 `map` 좌표 JSON과 Confluence 도면, 목적지별 경유 순서를 표시합니다. 1~4번은 최종 목적지가 아니라 경유·회전 지점입니다. [시뮬레이션 지도](index.html)는 같은 번호를 세로 배치도의 개념 위치에 표시하고 두 버거가 해당 지점을 통과하도록 경로를 나눕니다. WP1은 버거 1 초기위치, WP4는 버거 2 초기위치의 통로 합류점이며 WP3는 제작공정 합류점입니다. 경유점에서 Host 완료 단계를 추가하지 않습니다. 목적지별 순서는 [routes-burger1.json](routes-burger1.json)과 [routes-burger2.json](routes-burger2.json)에 있으며 실제 지도에서 확인해야 합니다. 실측 좌표를 시뮬레이션 픽셀에 그대로 환산한 것은 아니며 실제 Nav2·도킹 제어는 아직 연결되지 않았습니다.

[Host 관제](control.html)는 지도·시뮬레이션 엔진 없이 주문, 5개 장치 상태, 완료 조건, 카운트와 최근 Host 기록을 표시합니다. 공개 Pages에서는 미연결 안내만 보이며, Host PC에서 `python3 host/server.py`를 실행한 뒤 `http://127.0.0.1:8082/control.html`로 접속합니다. 실제 ROS 2 장치와 통신하려면 팀의 Host 어댑터가 ROS Action 결과를 검증한 후 [관제 API 계약](HOST_CONTROL_GUIDE.md)대로 상태를 보고하고 명령을 수락해야 합니다. 현재 패키지에 그 ROS 실행부는 아직 없습니다. 다음 단계 버튼은 어댑터가 모든 선행 조건 완료를 보고할 때만 활성화됩니다.

## Host 시스템 설정

주문 수량 범위·기본값, ROS 2 장치 주소, 작업 명령, 완료 판정, 다음 명령 조건은 **system-config.json**에서 관리합니다. [SYSTEM_CONFIG_GUIDE.md](SYSTEM_CONFIG_GUIDE.md)에 수정 위치와 적용 여부를 정리했습니다. `python3 host/system_config.py --write-web-policy`로 검증·웹 수량 정책을 생성한 뒤 Host를 재시작하세요. ROS 실행부는 아직 구현 전이며 해당 통신·완료 규칙은 연결 예정 설정입니다.

## 팀 개발 시작 패키지

웹사이트의 [다운로드 안내](downloads.html)에서 파일별 용도와 첫 실행 방법을 확인할 수 있습니다. `host-test.zip`은 이제 `robot3_host/` 구조로 제공됩니다. 루트 README에 개발 순서·역할 분담·인수 기준을 정리했고, `config/`, `robot3_interfaces/`, `robot3_orchestrator/`, `robot3_web_bridge/`, `robot3_mock_devices/`, `launch/`, `tests/`, `web/`을 포함합니다. ROS 폴더는 아직 실행 코드가 아닌 개발 명세입니다. 기존 웹 시험은 압축 해제 후 `python3 web/host/server.py`로 실행합니다. 저장소 자체에서 실행할 때는 기존 `python3 host/server.py`를 유지합니다. 패키지 구조 원본은 [team-template/README.md](team-template/README.md)입니다.

실물 연결 시 바꿀 설정·코드와 전환 순서는 [REAL_ROBOT_SETUP.md](team-template/REAL_ROBOT_SETUP.md)에 정리했고, 다운로드 ZIP 루트에도 포함합니다.

## 최신 출차 경로

초기위치·자재창고·제작공정·대기장소에서 짧은 10cm 후진 개념 표시 → 제자리180도 → 전진 주행으로 변경했습니다. 대기장소는 전진 주차합니다. 실제 로봇은 각 Pi에서 거리·yaw 확인 후 Nav2에 인계하도록 구현해야 합니다. [NAVIGATION_POLICY.md](team-template/NAVIGATION_POLICY.md) 참고. 새 기본값의 2개 주문은 8단계이며 과거 문서의 11단계는 이전 경로 기준입니다.

## 웹 → ROS 송신 시험 (2026-09-30)

팀원 코드의 `/web_to_ros` 상태 송신을 최신 버전에 통합했습니다. 로컬 웹에서 제품·수량·재생 여부를 기본 200ms마다 보냅니다. 설정은 `ros-config.js`, 실행 방법과 메시지 형식은 [ROS_BRIDGE_GUIDE.md](ROS_BRIDGE_GUIDE.md)를 참고하세요. 라이브러리도 ZIP에 포함되어 CDN 접속이 필요 없습니다. 실제 Action 명령·완료 수신은 아직 구현 전입니다.

## 한 화면 관제 배치 (2026-09-30)

데스크톱(뷰포트 1100×700 이상)은 화면 높이에 맞춰 왼쪽 현재 단계·완료 조건, 가운데 세로 지도, 오른쪽 주문·카운트·통신 상태를 배치합니다. 지도 아래에는 장비 상태가 표시됩니다. 사진·공정 이벤트·상세 완료 신호·통신 기록·실행 안내는 상단 **상세·기록**에서 확인하며 지도 위치를 눌러 사진을 바로 열 수 있습니다. 조건이나 통신 문구가 길면 해당 패널 안에서 스크롤합니다. 작은 화면과 확대 화면은 문서 흐름을 유지해 내용이 잘리지 않습니다. 레이아웃은 `dashboard.css`에서 수정합니다.
